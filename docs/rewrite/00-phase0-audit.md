Rules for the rewrite:

- Keep `applicationId`, the release keystore, `release.yml` signing + fingerprint check.
- `versionCode` must keep increasing (the release workflow already guarantees this).
- The Kotlin `namespace` (`com.example`) is internal and can change without breaking updates.
  It changes to `com.mtplayer.app` in the rewrite.
- Room database file `melody_player_local.db` holds user favorites and playlists. The
  rewrite imports them once into the new schema so users keep their data.

## 3. Root-cause map of broken features

### 3.1 Playback notification / MediaSession (critical)

- `MusicPlayerManager` drives a static `ExoPlayer` (`PlaybackService.sharedPlayer`) directly.
  No `MediaController` ever connects to the session.
- In Media3, a `MediaSessionService` only adds a session to its notification manager when a
  controller connects through `onGetSession`. With no controller, the session is never
  tracked, so the notification never appears and the service is never promoted to
  foreground. Background playback then dies when Android reclaims the process.
- `startService()` is called from `init` and wrapped in `try/catch`; on Android 8+ this
  throws when the app is in the background and the error is swallowed.
- `PlaybackService.onDestroy()` releases the shared player while the singleton manager still
  holds listeners; the next getter creates a fresh player and the queue is lost.

### 3.2 Resume and queue

- `restoreLastTrack()` restores a single-item queue, so the queue and shuffle order vanish
  after process death.
- Position is persisted on a 5 s timer from a UI-scoped coroutine only.

### 3.3 Favorites and add-to-playlist

- A fake playlist `favorites_default` mirrors the favorites table. Adding a song to it writes
  to `playlist_song_cross_ref`, but the UI reads it from `favorite_songs`, so the add looks
  like it failed.
- Every fresh install is seeded with fake playlists ("Workout Energy", "Late Night Chill").
- `fallbackToDestructiveMigration()` silently wipes favorites/playlists on any schema
  mismatch.

### 3.4 Video player and PiP

- The video player is a Compose overlay inside `MainActivity`, with its own `ExoPlayer`.
  Entering PiP shrinks the whole activity (library UI included) instead of just the video.
- PiP is button-only: no `setAutoEnterEnabled`, no `onUserLeaveHint`, no PiP remote actions,
  and controls are not hidden reliably in PiP.
- Orientation is forced to `SENSOR_LANDSCAPE` for every video, including portrait clips.
- Video playback has no media session, so no notification or headset control.

### 3.5 Video grid view

- Grid/list state is not persisted and the grid shares a parent `Column` with a
  `LazyRow` "Continue watching" strip plus a `weight(1f)` grid, which makes the grid
  scroll separately from the header and leaves blank space on small screens.

### 3.6 Mini player

- `MiniPlayerBar.kt` has previous / play / next only. There is no close button and no swipe
  to dismiss, so playback cannot be stopped from the mini player.

### 3.7 Library scan

- Audio selection is `IS_MUSIC != 0 OR DURATION >= min`. The `OR` lets ringtones and voice
  notes through whenever they pass the duration check; it should be an `AND`.
- Full rescan on every launch, all on one mutex, with no incremental update via
  `ContentObserver`.

### 3.8 Theme and contrast

- Old palette ("Sakura Rose" `#E8799B`, Midnight/Obsidian/Daylight surfaces) is spread
  across `Color.kt`, `Theme.kt`, the Room seed data and `ThemePreferenceEntity`.
- 59 hard-coded `Color.White` / `Color.Black` / `Color(0x…)` uses outside the theme package
  (video HUD, controls, media components). These are the light-theme readability bugs.
- The notification uses the default Media3 provider without a themed small icon accent.

### 3.9 Feedback surfaces

- 40 ad-hoc `Toast.makeText` / `AlertDialog` / `Snackbar` call sites with different styles.
  There is no single feedback system.

### 3.10 Build, release and security

- `gradlew` and `.github/scripts/*.sh` are committed without the executable bit
  (`100644`). CI works around it with `chmod`. Fixed in this phase.
- `isMinifyEnabled = false` for release: the shipped APK is 52.5 MB with 5 dex files.
- README claims API 37 / AGP 9.5 / Kotlin 2.4; the build actually uses compileSdk 36.1,
  AGP 9.1.1, Kotlin 2.2.10.
- The updater can embed a GitHub token XOR-"obfuscated" into `BuildConfig`. Anyone with
  the APK can recover it. The repository is public, so no token is needed. The rewrite
  removes token embedding entirely.
- `CrashLogger` writes stack traces to app-private storage (acceptable) but has no
  redaction of file paths in messages.

## 6. Plan

Each phase is committed and pushed to `rewrite/v2`, built and tested, reviewed against
this audit, then the next phase starts. After Phase 8 a single PR is opened into `main`;
merging it triggers the signed release.

| Phase | Output |
|---|---|
| 0 | This audit, environment, executable wrapper |
| 1 | Research notes, architecture, feature list, ADRs |
| 2 | New design system and every screen rebuilt |
| 3 | Music engine: MediaSessionService + MediaController, notification, queue, resume |
| 4 | Dedicated video activity: gestures, subtitles, PiP, resume |
| 5 | Library, favorites, playlists, history, search |
| 6 | Theme system and contrast tests |
| 7 | Hardening: R8, memory, ANR, crash handling, device classes, TV |
| 8 | Unit, Robolectric, and emulator tests with evidence |
